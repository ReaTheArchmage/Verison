DEV_LOG:
I will be using Cranelift to generate IR code from my .verison files. Cranelift generates intermediate representation code (IR) that is then
automatically parsed into machine instruction, handling all the architecture settings. Cranelift’s IR brakes down code into:
function: declares entities like stack slots and function signatures. Contains blocks.
block: a list of operations that ends with a terminator instruction.

Using a specific command while running the program, cranelift will emit the IR code, along with a bunch of other generated code, it
processes code in 3 main steps, resulting in 3 different files:
.unopt.clif -> Result of the translation of source code into unoptimized IR
.opt.clif -> Result of the optimization of .unopt.clif
.vcode -> Last formatting step before byte code emission
More in detail, Cranelift’s pipeline looks like this from a high level:
CLIF
legalizationmid-end egraph rewrites if enabled (optimization)
lowering to virtual register code (backend-specific)
regalloc (register allocation)
binary emission

On a single processor, multithreading gives the illusion of running in parallel.
In reality, the processor is switching by using a scheduling algorithm. Or, it’s
switching based on a combination of external inputs (interrupts) and how the threads
have been prioritized.
 
On multiple processor cores, threads are truly parallel. Individual microprocessors
work together to achieve the result more efficiently. There are multiple parallel,
concurrent tasks happening at once.
